充能球逻辑修改（Orb Channel）
替换了 OrbCmd.Channel 的充能流程（Base/Patches/OrbChannelPatch.cs）， 使充能球在激发时可以生成新的充能球而不会卡死，并修复充能球 UI 布局问题。

为什么修改

原版 OrbCmd.Channel 在「无充能球槽位」「充能球队列已满」等边界情况下 行为不可控，容易导致充能流程卡死或 UI 异常。UltraLib 用一个更安全的实现替换了它， 保证充能球机制在各种边界条件下都能正常工作——这也是新增充能球相关功能（如充能遗物）的依赖前提。

修改内容

新充能流程 SafeChannelInternal 依次执行：

  1. 空槽补槽：若玩家基础充能球槽位数为 0 且当前队列容量为 0，自动调用 OrbCmd.AddSlots(player, 1) 补 1 个槽位。
  2. 满队列自动激发：若队列已满，循环激发最旧的充能球（最多 10 次），为新的充能球腾出空间。
  3. 入队与演出：入队成功后写入战斗历史、播放充能音效、播放充能球动画。
  4. 布局修正：强制修正 NOrbManager 的充能球位置布局，并刷新控制器导航。
  5. Hook 触发：触发原版 AfterOrbChanneled Hook。
// SafeChannelInternal 核心流程（简化）
if (player.Character.BaseOrbSlotCount == 0 && orbQueue.Capacity == 0)
    await OrbCmd.AddSlots(player, 1);   // 空槽补槽

while (orbQueue.Orbs.Count >= orbQueue.Capacity && loopCount < 10)
    await OrbCmd.EvokeNext(choiceContext, player); // 满队列自动激发

if (await orbQueue.TryEnqueue(orb)) { /* 历史/音效/动画/Hook */ }

关键行为变化（重要）

✅ 去掉了角色判定：无槽位时所有角色都能获得充能球槽位
原版（及旧实现）在「空槽补槽」逻辑中有角色特判：
- 故障机器人：有「失去充能球槽位以换取增益」的机制，因此在槽位耗尽后 再生成充能球时，不会自动获得新槽位（原版设计如此）。
- 其他角色：因初始没有槽位、且故障机器人的多人牌会给队友充能球， 所以有一个特判——只有非故障机器人在无槽位时可以自动获得一个槽位。

UltraLib 去掉了这个角色判定：现在所有角色（包括故障机器人）在 BaseOrbSlotCount == 0 且队列容量为 0 时，都会自动获得一个充能球槽位。 这是刻意修正，目的是保证充能球机制（激发时生成新球、不卡死）对所有角色一致成立， 充能球相关功能（如 OrbHelper.Channel、充能遗物）在任何角色下都能正常使用。
